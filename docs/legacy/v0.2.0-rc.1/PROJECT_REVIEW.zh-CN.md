# v0.2.0-rc.1：项目分析、开发结果与发布判断

日期：2026-09-21
输入：用户提供的 `context-memory-manager-v0.1.0-frozen-2026-09-21.zip`
产物：本地完成的完整源码、预构建运行文件、npm 本地安装包、验证记录与变更补丁。未上传 GitHub，未发布 npm。

## 一、这个项目真正值得做的地方

核心用户不是来研究一套记忆算法的人，而是已经使用 Coding Agent、被长工具结果反复占满上下文的人。他需要的是：长任务还能继续；换会话后关键证据还在；摘要漏掉细节时能找回；接入出错不能把原本可用的 Agent 弄坏。

因此，产品应当是“可找回证据的工具上下文层”，而不是又一个只能返回模糊摘要的记忆数据库。关键闭环是：

**看到真实工具结果 → 保存正确原文 → 在宿主允许的边界缩减可见内容 → 需要时精确找回。**

没有宿主接入，评分算法再复杂也只是 Core 演示；没有可信归档，压缩越积极风险越高；没有清楚的能力边界，配置成功反而会误导用户以为已经节省上下文。

100K Star 只能作为产品吸引力的目标，不能作为测试通过条件。本轮不通过加大量旁支功能来模拟“成熟”。

## 二、对原版的判断

原版并非空壳：已有 SQLite 存储、Blob、压力与保留策略、Jev 评分、胶囊摘要、链、固定、找回、清理和 38 项测试。这些是值得保留的内核。

但它更接近经过测试的原型，而不是普通 Agent 用户能直接安装的产品。主要断点是：

1. **功能没有落到宿主边界。** 缺少可实际运行的四平台接入、可靠 MCP 服务/代理、真实子进程桥接，以及安装和卸载闭环。
2. **“归档了”不一定等于“归档的是这次结果”。** 重复标识、跨会话来源变化、工作区隔离、归档完整性和清理顺序存在需要修复的边缘情况。
3. **测试覆盖不足以支撑发布措辞。** Core 单测不能证明宿主接口正确、打包不漏文件、子进程协议可互操作、配置不会误覆盖。
4. **统计与能力容易被过度解读。** 算法估计的 Token、输出字符减少、模型 API 账单、宿主实际收到的上下文是不同量，必须拆开。

原始需求文档与开发日志已保留在 `docs/legacy`，没有删掉历史依据；它们不再冒充当前能力说明。

## 三、本轮实际开发了什么

### 1. 先补证据可靠性

工具事件标识改为 Agent、规范化项目、会话和工具调用 ID 的组合。相同内容重试幂等；同一完整标识对应不同内容时保留原档并报告冲突，调用方继续使用本次原结果。

跨会话恢复改为独立视图，不再改写源事件归属。同一项目的多个 Agent 不再因工作区单键冲突而混淆。schema v3 迁移事务化；未来版本数据库会被拒绝而不是降级。

文本和 Blob 都校验 SHA-256 与字节长度；路径必须符合内容寻址规范，阻止路径越界和符号链接逃逸。发现 Node/SQLite TEXT 对 NUL 的截断边缘情况后，新增含 NUL 字符串强制 Blob 路径。Unicode 分页不会拆开代理对。

GC 先提交数据库引用退役，再删除无引用 Blob，并保护共享内容、固定、工作链与回读视图。默认不自动删除原文。

### 2. 做出用户能用的运行层

新增按项目和 Agent 作用域隔离的 MemoryService，串起捕获、证据检索、分页回读、完整导出、固定、诊断、校验、重建索引与投影视图凭据。

新增五个记忆工具和有界 stdio MCP 服务。工具型 MCP 代理只转换可安全处理的纯文本，不碰结构化输出、图片、错误、输出 schema 等。工具只调用一次；超时或丢响应不能自动重试有副作用的操作。

新的 CLI 有帮助、离线演示、四平台 setup/uninstall、doctor、归档浏览和安全配置。预览不创建数据库；完整导出不覆盖现有文件；原生 Hook 出错保留原结果。

### 3. 分平台实现，而不是写一个虚假的“全平台支持”

**OpenCode** 是历史投影主路径：实验性消息变换钩子加常驻 Node 桥接，宿主 Bun 不直接加载 SQLite；新结果首次呈现受保护；插件重启能够识别已有归档与投影，并支持固定后的原文恢复。非 Git 项目的根目录哨兵不能把多个项目混成一个作用域。

**Claude Code** 使用官方 Hook 的形状保持替换，当前仅缩减符合契约的成功 Bash stdout，其余字段保持。它是新结果入口压缩，不是任意改写历史消息。

**Codex** 归档官方 PostToolUse 提供的信息，并通过 MCP 检索。没有滥用 `decision: block` 来强行“压缩”。

**Kimi** 通过临时配置启动已有 CLI，保存原模型与 MCP 配置，增加成功/失败 Hook。没有稳定调用 ID 时生成独立观察 ID，不把两次相同结果伪装成同一次调用。当前原生路径仅归档与找回。

### 4. 收紧模型与统计行为

离线默认路径可运行，不要求用户先买模型。非法 JSON、字符串分数、NaN、越界分数不能被当成合格评分；提供商顺序失败切换真正包含响应验证。异步评分后再次检查固定状态，避免用户刚固定又被压缩。

摘要证据以确定性提取为底，模型凭空增加的事实和路径不会直接成为权威证据。长日志会检查尾部的汇总与失败信息。无法定价的模型不再套用猜测价格；数值零只作为未定价的兼容哨兵，CLI 不把它显示成实际免费账单。

错误诊断不回显 JSON 解析源正文或外部接口错误正文，避免额外制造一份私密记录。这不改变原始归档本身未加密的事实。

### 5. 做到可交付，而不仅是工作目录能运行

源码包带预构建产物，Node 可直接运行；本地 npm tarball 经离线隔离安装，验证 help、完整演示、四平台安装/卸载和独立 MCP 握手。安装器预览、备份、幂等、识别自己的配置、检测并发修改；卸载保留非 CMM 设置和归档。

补充了中英文 README、架构、接入边界、运行维护、安全说明、变更日志、MIT 许可证、贡献说明、Agent 开发约束及多平台 CI 配置。

## 四、真实证据，而不是宣传数字

原版 38 项测试通过；当前本地最终回归为 **99 项通过、0 失败、0 跳过，18 个 suite**。新覆盖包括三个独立进程写同一个数据库、共享 Blob、原始 v0.1 DDL 的真实约束迁移、独立协议客户端、实际 Node 桥接、配置冲突、卸载回滚、错误输出保留、取消和不重试。

演示把 177,046 个 UTF-16 字符单元缩为 7,950，15 页找回全部原文，SHA-256 一致。它证明这条可恢复链路能工作，**不证明真实 API 节省 95.51%，不证明模型任务质量不下降**。

测试清单、命令与边界见 `RELEASE_VALIDATION.md`；缺陷到修复的映射见 `AUDIT.md`。

## 五、为什么仍然叫发布候选版

没有在 Windows 桌面实际操作四个 CLI，没有在真实 OpenCode/Bun 内完成任务，也没有调用用户的付费模型。GitHub CI 只是已配置，未远程执行。这些不能用更多单测替代。

MCP 是明确限定的 tools-only stdio 子集，不是完整协议网关；OpenCode 使用实验性钩子；Kimi Hook 为 Beta。宿主版本变动会影响兼容性。归档只能保存实际观察到的内容，无法找回宿主先前已经截掉的数据。

搜索不是全文或语义检索保证；每页回读会验证整份原文，超大文件多页读取有额外磁盘与哈希开销；清理不是硬磁盘配额，也没有自动清理孤立 Blob。局部哈希一致性不是权限安全边界。

因此，本轮适合发布为供技术用户测试的 RC 源码，而不是无条件宣称生产认证的稳定版。

## 六、下一步最值得投入的验证

优先在用户实际 Windows 机器、真实 Agent 版本上跑一条同样可复现的任务：安装后观察状态、大日志出现、后续历史变短或明确保持 capture-only、原文找回、固定、重启、卸载。记录宿主版本和实际输出，不依赖“应该兼容”。

随后对少量真实长任务做带/不带 CMM 的对照：任务是否完成、找回次数、是否误删关键证据、宿主实际输入 Token 与耗时。先决定压缩默认值是否合适，再考虑更复杂的模型和检索。不要先建设账户、团队后台、排行榜或大规模基准框架。

这些是尚未完成的验收项，不是后台正在执行的承诺。当前交付保留了完整代码与复现方式，可以从明确证据继续迭代。
